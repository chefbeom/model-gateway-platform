# 시스템 연결도

시스템 구조 화면은 참고용 정적 아키텍처 그림이 아니라 선택한 워크스페이스의 관리 API 응답으로 연결도를 구성합니다.

## 표시 구조

프로젝트·API 키 → Gateway → 논리 서비스 → 모델 Deployment(Target) → Runtime 또는 외부 Provider 순서입니다. 프로젝트의 서비스 권한은 `service-access` 응답의 서비스 ID로, Target은 `deploymentId`로 연결합니다. 여러 서비스가 같은 모델·서버를 공유할 때 해당 노드는 하나만 표시합니다. 팀은 프로젝트 소유 정보로 표시하며 GPU/Node를 별도 실행 서버로 중복 계산하지 않습니다.

- 노드 선택: 관련 호출 경로 강조, 상태 사유·Endpoint·컨텍스트·Capability·정책·연결 관계 상세 확인.
- 연결선 선택: P 우선순위, 상대 가중치, 활성·Degraded 여부, 모델 고정/추적 설정과 상태 사유 확인.
- 프로젝트 필터: 부여된 서비스 권한에 연결된 경로만 표시. 외부 Provider 승인·만료·자동 Failover 설정도 해당 프로젝트 기준으로 표시.
- 서비스 필터: 해당 서비스와 권한 프로젝트·모델·서버만 표시.
- 미연결 모델: 기본적으로 접어 두며 체크 시 등록 모델도 포함. 실제로 없는 Target 연결을 만들지 않음.
- 확대·축소와 화면 맞춤: 화면 폭에 맞춰 표시하고 좁은 화면에서는 연결도 영역 안에서 스크롤.
- 전체 구성 목록: 팀·사용자·프로젝트·키·서비스·서버의 기존 목록은 접은 상태로 보존.

## 상태의 의미와 한계

초록은 마지막 정상 검사 기록 또는 활성 설정, 노랑은 미로드·복구·Drain·Degraded, 빨강은 장애·인증 설정·권한 확인, 회색은 비활성·정보 미확인입니다. 각 노드의 설명에서 설정과 검사 기록을 구분합니다. `loaded=false` 모델을 HEALTHY만으로 로드됐다고 판정하지 않습니다. 외부 모델에는 로컬 로드 상태를 적용하지 않습니다.

연결선은 저장된 요청 후보이며 실시간 트래픽, 현재 Circuit Breaker, Quota 잔여량, 요청별 Capability 및 데이터 보호 판단이나 최종 Failover 결과를 보장하지 않습니다. P가 작을수록 우선이며 상대 가중치는 확률(%)이 아닙니다.

Gateway 아래의 MariaDB는 프로젝트 표준 배포 저장소, Redis/LOCAL은 실제 배포 프로필의 공유 상태 설정, 요청 추적·Usage는 Gateway의 기능 관계입니다. 이 페이지는 DB 또는 Redis PING을 수행하지 않습니다. Prometheus/Grafana의 배포·건강 상태도 추측하지 않습니다.

오프라인이어도 등록 모델·Target ID를 보존합니다. 조회 권한/연결 실패로 모델 정보를 얻지 못한 경우 미확인 참조 노드로 표시하고 실제 누락과 구분합니다. API 키 원문과 Endpoint URL의 인증 정보·query는 연결도에 표시하지 않습니다. 새로고침은 구성 조회만 수행하며 모델 로드·삭제·정책 변경을 하지 않습니다. 조직 변경 시 이전 비동기 응답이 새 조직의 구성에 섞이지 않도록 조회 버전을 검사하고 한 번에 반영합니다.

## 검증

`frontend`에서 `npm run test:topology`와 `npm run build`를 실행합니다. 테스트는 실제 ID 관계, 프로젝트 범위, 로드 상태, 오프라인 참조 보존, 부분 조회 실패, 외부 권한·만료, 미연결 모델, 설정/헬스 구분, 비밀값 비노출 및 배치 경계를 검증합니다.
