# Runtime·모델 사용량 통계

사용량 화면의 상세 통계는 선택한 조회 기간과 프로젝트 접근 범위에 맞춰 일반 Gateway API 요청을 등록된 Runtime/외부 Provider 및 실제 Deployment에 연결해 집계합니다. Platform administrator와 Organization administrator는 조직 전체를 볼 수 있고, Project owner와 Developer는 기존 사용량 화면과 동일한 프로젝트/API 키 권한 범위만 봅니다.

## 집계 범위와 요청 귀속

- **Gateway API 요청**: `llm_request` 한 행을 논리 요청 한 건으로 셉니다. 성공·실패율과 비용, 사용자에게 반환된 토큰은 논리 요청 기준입니다.
- **Runtime Attempt**: 라우팅 과정에서 실제로 시도한 Deployment마다 한 번 셉니다. Primary 실패 후 failover 성공도 Primary 실패 Attempt와 Secondary 성공 Attempt로 각각 표시합니다. 따라서 Attempt 수는 논리 요청 수와 다를 수 있습니다.
- **Runtime/모델의 완료 요청**: 응답을 최종 완료한 Deployment에 귀속합니다. 최종 배포 대상이 정해지기 전 실패한 요청은 `대상 미확정`에 표시합니다. 실패 모델을 놓치지 않도록 모델별 실패는 Attempt 표에서 함께 확인합니다.
- **모델 테스트 콘솔**: 직접 Chat 테스트는 `playground_request`로 별도 집계합니다. 운영 API 요청·비용과 합산하지 않습니다. 테스트 이력에는 청구 단가 스냅샷이 없으므로 비용을 계산하지 않습니다.

## 표시 지표

| 영역 | 지표 | 정의 |
| --- | --- | --- |
| 요청 | 요청 수, 성공/실패/진행 중, 성공률 | 성공률 분모는 완료된 요청(성공+실패)이며 진행 중은 제외 |
| 장애 전환 | Failover 요청 수, 전환 횟수 | 요청에서 실제 failover가 발생했는지와 전환 횟수 |
| Runtime Attempt | 시도 수, Attempt 성공/실패, Attempt 성공률, 응답시간 | Runtime/모델 단위 개별 호출; 전환 전 실패 포함 |
| 지연시간 | 평균·최솟값·최댓값 | 기록된 `latencyMs` 표본만 사용 |
| 토큰 | 입력·출력·전체 평균·최솟값·최댓값, 총량 | 각 필드가 기록된 표본만 사용; 전체 토큰 통계는 입력과 출력이 모두 있는 요청만 포함 |
| 보조 토큰 | 추론 토큰, 캐시 입력 토큰 | Provider가 usage로 돌려준 값의 합계 |
| 비용 | 통화별 예상 비용, 미산정 요청 | 등록된 가격 기준의 추정 비용; KRW와 USD를 합산하지 않음 |
| 요청 구성 | TEXT, VISION, STRUCTURED_OUTPUT, TOOL_CALLING 및 조합 | capability 유형은 서로 중복될 수 있어 비율 합계가 100%를 넘을 수 있음 |
| 실행 모드 | 스트리밍, reasoning effort, 요청 tier → 실제 tier | 요청/응답에 보존된 메타데이터를 사용; 미지정·확인되지 않은 값은 별도 분류 |
| 오류 | 최종 요청 오류 코드, 모델별 Attempt 실패 유형 | 상세 원문 오류 메시지는 집계에 사용하지 않음 |
| 추세 | 일별 또는 월별 요청·성공·실패·토큰 | 92일 이하 범위는 일별, 그보다 긴 범위는 월별 |

## 데이터 정확도와 개인정보

- 평균·최솟값·최댓값은 표본 수(`n`)와 함께 표시합니다. 값이 없는 실패 토큰을 0으로 대체하지 않습니다.
- 토큰 값은 Provider가 반환한 usage이거나 Gateway가 계산한 추정치일 수 있습니다. 현재 데이터 모델에는 출처를 구분하는 필드가 없어 두 종류를 분리해 검증할 수 없습니다.
- Structured Output 분류는 response_format.type=json_schema 기준입니다. json_object는 JSON mode로 요청 기능 분류에 포함되지 않습니다.
- 모델별 일반 API 사용량은 최종 Deployment 귀속이며, 해당 모델이 처리 중 실패했지만 failover된 횟수는 Attempt 실패 통계에서 확인합니다.
- Fast tier는 별도 임의 추정하지 않고 요청된 tier와 Provider가 응답한 실제 tier를 분리해 표시합니다.
- 가격 이력이 없거나 계산할 수 없는 요청은 비용 0으로 가장하지 않고 미산정으로 셉니다.
- 프롬프트, 응답 본문, 이미지/PDF 파일, API 키 원문을 통계에 저장하거나 반환하지 않습니다. 요청 유형·상태·오류 코드·토큰·시간과 같은 운영 메타데이터만 사용합니다.
- 기존 모델 테스트 로그에는 modality가 저장되지 않았으므로 `UNKNOWN`으로 남습니다. 배포 이후 생성되는 테스트 요청부터 요청 유형·추론 수준·tier를 기록합니다.

## 확인 절차

1. **사용량** 화면에서 조직/프로젝트 범위와 날짜 구간을 선택합니다.
2. `등록 서버·모델 상세 통계`에서 사용량·Attempt·모달리티·추론/tier·오류 분포를 확인합니다.
3. 모델별 특정 실패가 보이면 **관측성 → 요청 탐색기**에서 상세를 열어 Attempt와 구체적인 진단 정보를 확인합니다.
4. 직접 테스트 결과는 아래 `모델 테스트 콘솔 통계`에서 운영 API와 분리해 확인합니다.
